# Планирование последовательностей интенций поверх замороженных FB-представлений

Реализация high-level механизма, который рассуждает не об одной следующей
интенции, а о **последовательности** интенций, и за счёт этого работает лучше на
длинных горизонтах. Всё строится поверх замороженных `F`, `B`, `pi_l` и `pi_h`
из статьи [Switching Successor Measures for Hierarchical Zero-shot RL](https://arxiv.org/abs/2605.13207)
(Stojanovic & Proutiere, 2026) — ничего не обучается и не дообучается.

Подробный разбор метода и результатов — в [REPORT.md](REPORT.md).

## Идея за одну минуту

Из Теоремы 1 статьи берётся величина, которая уже стоит в лоссе авторского
high-level контроллера:

```
p(s → w) = M(s → w) / M(w → w) = F(s, ẑ_w)ᵀB(w) / F(w, ẑ_w)ᵀB(w) ≈ E[ γ^H(s→w) ]
```

Это безразмерная дисконтированная вероятность достижения `w` из `s`: нормировка
сокращает и плотность данных, и масштаб `B`. По строго марковскому свойству она
**мультипликативна** вдоль цепочки подцелей, а значит

```
c(s → w) := −log p(s → w)   —   аддитивна.
```

Выбор наилучшей последовательности интенций становится задачей кратчайшего пути
с неотрицательными весами. Одношаговый бейзлайн — это её частный случай с
глубиной 1.

Метод целиком работает на этапе вывода: узлы графа берутся из оффлайн-датасета,
рёбра считаются форвард-проходами замороженной `F`, маршрут ищется Дейкстрой.

### Две детали, без которых ничего не работает

Обе найдены замерами на реальном чекпоинте, обе разобраны в [REPORT.md](REPORT.md).

**Знаменатель — это `max_s M(s → w)`, а не самомера `M(w → w)`.** Сеть не строго
пикована в `w`, поэтому сырое отношение для близких пар превышает единицу, клип
обнуляет стоимость, а top-k отбирает в рёбра именно самые дешёвые — то есть
ровно вырожденные. В первой версии так обнулилось 99.6% рёбер. Теория даёт
`M(w → w) = max_s M(s → w)`, и максимум по опорным состояниям и устойчивее, и
гарантирует `p ≤ 1`.

**Узел — это НАБОР состояний, а не одно состояние.** Наблюдение antmaze
29-мерно: это поза муравья, а не точка на плоскости. Корреляция `c(s → w)` с
истинным геодезическим расстоянием: **0.18** для одиночной позы и **0.70** для
набора состояний одной локации. Набор берётся окном подряд идущих состояний
траектории — за несколько десятков шагов агент почти не смещается, зато поза
меняется полностью. Порядок операций важен: сначала агрегировать набор
максимумом достижимости, потом нормировать.

Цена: узел из `W` состояний означает `W` столбцов в каждом запросе к `F`, то
есть построение графа и планирование дорожают в `W` раз. Отсюда Colab-first.

## Установка

```bash
git clone --recursive <url этого репозитория>
cd fb-multi-intention-planning
```

Если репозиторий уже склонирован без `--recursive`:

```bash
git submodule update --init --recursive
```

Окружение (Linux / Colab, с GPU):

```bash
python -m venv .venv && source .venv/bin/activate && pip install -r requirements-colab.txt
```

Локально на Windows GPU-сборок JAX не существует, поэтому только CPU:

```bash
python -m venv .venv && .venv\Scripts\activate && pip install -r requirements-cpu.txt
```

Датасеты:

```bash
python scripts/download_datasets.py --datasets antmaze-medium-navigate-v0
```

Это обёртка вокруг штатной загрузки OGBench: авторская версия падает на Windows
(`PermissionError: [WinError 32]`), потому что переименовывает временный файл, не
закрыв его. На Linux/Colab можно пользоваться и обычным `ogbench`.

## Чекпоинты

Нужна директория с `params_*.pkl` и `flags.json` — та, что сохраняет авторский
`main.py`. Внутри должны быть все четыре модуля:
`modules_forward_repr`, `modules_backward_repr`, `modules_actor`, `modules_high_actor`.
Загрузчик проверяет их наличие и падает с внятной ошибкой, если чего-то нет.

## Запуск

Основной прогон — бейзлайн против планировщика, 5 сидов, 20 эпизодов на задачу:

```bash
python scripts/run_eval.py --checkpoint_dir /path/to/antmaze-medium --methods baseline,graph --seeds 0,1,2,3,4 --num_episodes 20
```

Проверка гипотезы про горизонт (E1):

```bash
python scripts/analysis_composability.py --checkpoint_dir /path/to/antmaze-medium
```

Карты ценности и качество графа (E2, E5):

```bash
python scripts/analysis_value_maps.py --checkpoint_dir /path/to/antmaze-medium --task_id 1
```

Тесты логики планирования (чекпоинт не нужен, секунды):


## Как устроено сравнение

Чтобы результатам можно было доверять:

* **Бейзлайн — авторский код.** `SingleIntentionController` вызывает
  `agent.sample_actions` из upstream, а не нашу реализацию.
* **Одинаковый вход.** Оба метода получают только оффлайн-датасет,
  переразмеченный reward-функцией задачи. Целевой узел планировщика — это
  состояния датасета с `reward = 1`, а не привилегированное `info['goal']`.
  Латентная задача `z_r` у обоих одна и та же, из `agent.infer_latent`.
* **Парные эпизоды.** Эпизод `i` задачи `t` стартует с
  `env.reset(seed=f(сид, t, i))`, поэтому оба метода видят побитово одинаковые
  начальные состояния. Разброс от случайности стартов из сравнения уходит.
* **Отсутствие регрессии.** Если граф не предлагает маршрута, планировщик
  откатывается на поведение бейзлайна; это зафиксировано тестом.
* **Доверительные интервалы** бутстрэпом по сидам, а не «среднее ± std».

Привилегированная геометрия лабиринта (координаты, карта стен) используется
**только** в скриптах анализа, чтобы построить графики и измерить долю
ошибочных рёбер. В самом методе её нет: см. `fbplan/maze_analysis.py`.

## Структура

```
fbplan/
  fb_api.py        оракул поверх замороженных F и B: p(s→w), c(s→w), политики
  nodes.py         отбор узлов графа farthest point sampling в B-пространстве
  graph.py         построение графа, прунинг рёбер, Дейкстра до цели
  planner.py       онлайн-контроллер: выбор подцели, переключение, откат
  controllers.py   бейзлайн (авторский) и неиерархический референс
  task_setup.py    zero-shot протокол: z_r и целевые состояния из датасета
  rollout.py       единый цикл прогона для всех методов
  stats.py         бутстрэп и парные сравнения
  experiment.py    сборка среды, агента, оракула, графа
  maze_analysis.py геометрия лабиринта — только для анализа
scripts/           запуск оценки, анализ, загрузка данных
tests/             синтетический лабиринт с известными расстояниями
third_party/       upstream-репозиторий статьи (submodule, пин на коммит)
```

## Калибровка гиперпараметров

Пороги планировщика задаются в шагах среды и переводятся в стоимости через
`c = −H·log γ`. Масштаб взят из самих данных `antmaze-medium-navigate-v0`:

| величина | значение |
|---|---|
| размер клетки | 4.0 мировых единицы |
| медианное смещение за 50 шагов | 4.6 единиц ≈ 1.1 клетки (~11 шагов на единицу) |
| длина задач (геодезически) | 24–40 единиц, то есть 260–440 шагов |
| эффективный горизонт при γ = 0.99 | 100 шагов ≈ 9 единиц ≈ **2.3 клетки** |

Последняя строка — суть проблемы: горизонт дисконтирования примерно вчетверо
короче задачи, поэтому прямая FB-оценка до далёкой цели равна `γ^400 ≈ 0.018`
и тонет в шуме низкорангового приближения.

Воспроизвести эти числа (чекпоинт не нужен):

```bash
python scripts/calibrate.py
```

Отсюда дефолты: `--max_edge_steps 75` (ребро ≈ полторы клетки, оценка ещё
уверенная), `--reach_steps 20` (подцель достигнута), `--replan_every 10`.

Размер набора узла подобран замером корреляции с истинным расстоянием: 0.30 /
0.46 / 0.51 / 0.53 при `--num_members` 1 / 8 / 16 / 32. После 16 отдача падает,
а стоимость растёт линейно, поэтому дефолт `--num_members 16 --member_stride 4`
(охват окна 64 шага ≈ полторы мировых единицы).

На CPU полная конфигурация непрактична. Локально осмысленный минимум:

```bash
python scripts/run_eval.py --checkpoint_dir checkpoints/medium --methods baseline,graph --seeds 0 --num_episodes 20 --num_nodes 300 --num_members 8 --member_stride 8 --normalizer_references 1000 --replan_every 20
```
